# 部署说明

## 支持的生产环境：Sites

此代码依赖 Sites 提供的可信登录身份与 Cloudflare D1 / R2 绑定。以下步骤需要具有 Sites 创建与发布权限的 Codex / ChatGPT 会话及其 Sites 插件。

1. 将本 GitHub 仓库作为来源，要求创建一个全新的 Sites 站点。当前源码的 `.openai/hosting.json` 只声明 `DB` 和 `BUCKET`，不含任何现有站点的 project ID。新站点注册后，应把返回的新 ID 写入该新站点的部署 checkout；不要在开源模板中提交个人站点 ID。
2. 由 Sites 创建 `DB`（D1）及 `BUCKET`（R2）。依次应用 `drizzle/0000`、`0001`、`0002` 三个迁移。不要复制作者私人站点的数据库、R2 对象、历史记录或运行时环境变量。
3. 运行 `node scripts/generate-encryption-key.mjs` 生成仅供该部署使用的密钥。在 **Site settings → Environment variables** 中添加 `ZTOKEN_ENCRYPTION_KEY`，启用 **Secret**。密钥必须为 32 个随机字节的 Base64 字符串。生成过程在本机进行；不要将值粘贴进聊天、源码、issue 或 README。
4. 先以私人站点完成构建、迁移和登录验证。默认模型配置可由每位访问者在 API 设置中覆盖。没有站长提供的共享模型密钥；每位用户自行提供 ztoken 密钥。
5. 用两个独立登录账号验证：A 的记录、文件、API 设置及个人素材不能被 B 读取、覆盖或删除；B 默认可使用作者共享素材。验证真实上传、评分、推荐回答和失败重试。
6. 需要开放在线服务时，将**新站点**访问范围设为公开。公开访问不代表可匿名读写用户数据；应用仍要求登录后使用工作台。不要改变作者原有私人站点的访问范围。

托管站点的创建、秘密值保存与正式部署是实际操作步骤，GitHub 上传不会自动完成它们。若当前 Sites 工具不支持从既有站点创建独立副本，应保留独立源码，等待支持的创建方式，不能把私人站点改成公共实例代替。

## 运行环境变量

| 名称 | 用途 | 是否公开 |
| --- | --- | --- |
| `ZTOKEN_ENCRYPTION_KEY` | AES-256-GCM 加密用户保存的 ztoken 密钥 | Secret，不能公开 |

轮换该加密密钥后，之前保存的 API 密钥将无法解密，用户需重新保存。API 密钥由每位用户通过网站的 API 设置填写，不写入构建环境。

## 不适用于 GitHub Pages

GitHub Pages 仅用于静态内容。此平台包含服务端模型调用、身份检查、D1 和 R2，不能只上传 `dist` 到 Pages 即获得完整服务。

## 普通 Cloudflare Workers

当前代码不可直接作为没有身份网关的公网 Worker 发布。`oai-authenticated-user-*` 只能在 Sites 保证可信身份注入的环境下使用；在普通 Worker 上直接信任请求者自带的这些头会导致身份伪造。

如需独立 Cloudflare 部署，必须先接入并验证实际身份提供方、替换 `app/chatgpt-auth.ts` 与登录入口，再配置自己的 D1 / R2、部署流程及权限测试。仓库目前不宣称支持这一部署方式。

## 验证边界与运维

本地测试不验证托管方登录，也不代替真实 API 兼容性与音频质量检查。公开实例的站长承担存储、托管和运维费用；各用户的模型调用费用由自己的 ztoken 账户承担。正式开放前应按部署平台能力设置流量和存储额度，并提供联系渠道。
